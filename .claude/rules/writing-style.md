# 글쓰기 규칙 (writing-style)

> 도메인 규칙은 PROJECT overlay 다. 이 블로그에서 "좋은 글이란 무엇인가"를 정의한다.
> dod-checker(결정론 검출)와 design-grill(설계 질문)이 이 파일을 근거로 삼는다.
> CLAUDE.md 에서 `@.claude/rules/writing-style.md` 로 import 되어 글 쓸 때 자동 적용된다.

## 적용 대상

- `src/content/blog/**/*.md`, `**/*.mdx` (블로그 본문)
- `src/pages/about.astro` 등 산문이 들어가는 페이지

## 규칙 (해야 할 것 / 하면 안 되는 것)

기계가 검출 가능하게 적을수록 dod-checker 가 강하게 잡는다.

- **앰대시(—, U+2014) 금지.** 글로벌 규칙. 대신 콜론(:), 쉼표(,), 마침표(.)로 분리한다.
  본문에서 발견 = **FAIL**. (엔대시 – 는 범위 표기 등 본래 용도면 허용)
- **검증된 사실만 쓴다.** 직접 실행/구현/공식 문서로 확인하지 않은 수치·주장은 쓰지 않는다.
  정량 수치(성능, 버전, 한계값)는 권위 소스(공식 문서/릴리스 노트)로 재확인한 것만. 미확인 = grill 에서 질문 대상.
- **OREO 구조 우선.** 문단은 결론(Opinion) → 근거(Reason) → 예시(Example) → 재확인(Opinion) 흐름. 요점을 먼저 던진다.
- **표·불릿 우선.** 비교·나열·단계는 산문보다 표/불릿으로. 벽글 금지.
- **결정과 교훈을 남긴다.** "무엇을 만들었나"보다 "왜 그렇게 결정했나 / 무엇을 배웠나"에 무게를 둔다 (이 블로그의 원칙).

## 근거 / 왜 이 규칙인가

- 앰대시: 글로벌 작성 스타일 정책. 한글 문장에서 앰대시는 문장 구조를 흐린다.
- 검증된 사실만: 기술 블로그의 신뢰는 한 번의 틀린 수치로 무너진다. `build-to-blog` 스킬의 핵심 계약.
- OREO / 표 우선: 스캔하며 읽는 독자가 요점을 놓치지 않게.

## 회색지대 / 예외

- 인용문·코드블록 안의 앰대시는 원문 보존이 필요하면 허용 (dod 는 코드펜스 밖만 FAIL 로 본다).
- 사용자가 명시적으로 앰대시를 원하면 그때만 예외 (글로벌 규칙).

## 관련

- 스킬: `build-to-blog` (조사 → 구현 → 검증 → 공식소스 대조 → 초안)
- 글로벌 정책: `~/.claude/CLAUDE.md` (앰대시 금지)
- 검증: dod-checker `[E]`(앰대시)·`[G]`(사실확인 WARN), design-grill 축 1·3
