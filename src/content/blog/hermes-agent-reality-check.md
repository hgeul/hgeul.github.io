요즘 X와 해커뉴스에서 Hermes Agent라는 이름이 자주 보였다. 처음엔 또 하나의 LLM 래퍼겠지 하고 넘겼는데, GitHub 별 17만 5천이 4개월 만에 붙었다는 숫자를 보고 마음이 바뀌었다. 이 정도 속도면 적어도 어디 한 군데는 사람들 가려운 데를 긁었으니까.

며칠 짬을 내서 공식 문서, 보안 감사 리포트, 후기 글을 훑었다. 매력적인 도구는 맞더라. 그런데 깔고 쭉 쓰면 되는 도구는 아닌 것 같아서 왜 그런지 정리했다.

## Hermes Agent란?

직접 서버에 깔아서 메신저와 묶어 쓰는 장기 실행형 AI 에이전트다. NousResearch가 2026년 2월에 공개했다. 매력은 셋.

- **self-hosted**: 내 머신에 깔리고, 텔레메트리도 클라우드 락인도 없다. 데이터는 내 디스크에 머문다.
- **메신저 통합**: 텔레그램, 디스코드, 슬랙, 왓츠앱, 시그널, 이메일까지 20개 넘는 채널을 하나의 게이트웨이 프로세스로 묶는다. "내 비서를 텔레그램에 두고 부른다"가 실제로 가능해진다.
- **스킬을 스스로 만든다**: 셋째이자 진짜 차별점. 다른 에이전트와 가장 크게 다른 부분이다.

## 진짜 차별점: 스킬을 스스로 만든다

평소 ChatGPT나 Claude를 쓰다 보면 답답한 순간이 있다. 어제 알려준 절차를 오늘 또 설명해야 한다. 메모리 기능이 있어도 "내가 누구다" 정도지, "이 작업은 이렇게 한다"가 누적되진 않더라.

Hermes는 다르다. 복잡한 작업(보통 도구 호출 5번 이상)을 끝내면 그 절차를 `SKILL.md` 파일로 자동 작성한다. 다음에 비슷한 요청이 오면 그 파일을 불러와 그대로 실행하고, 새 엣지 케이스를 만나면 스킬을 업데이트한다.

이와 별개로 백그라운드 회고 패스가 주기적으로 돌면서 "이번 세션에 뭐가 잘 됐지"를 보고 워크플로 파일로 저장한다.

이게 진짜로 되더라. 사람들이 처음 열광한 게 이거였다. "오래 쓸수록 똑똑해진다"는 문구가 실제로 돌아간다.

## 그런데 깔고 쭉 쓰면 되는 게 아니다

나도 처음엔 그렇게 생각했다. 깔아두고 메신저 연결하고 잡일 시키면서 알아서 똑똑해지길 기다리면 되는 거 아닌가.

아니었다. 적어도 디폴트 그대로는 아니다. 위험을 네 가지로 확인했다.

### 위험 1: 디폴트 보안 자세가 ALLOW-ALL이다

이 부분은 마케팅 페이지엔 거의 안 나와서 보안 감사 리포트를 직접 봐야 보이더라. GitHub 이슈 #7826에 공식 감사 결과가 올라와 있고, Critical 4건, High 9건이 잡혔다.

- `env_type` 기본값이 `local`인데, 이 상태에서는 LLM이 **호스트 셸 명령을 무엇이든 실행 가능**하다.
- `read_file` 도구엔 deny list가 없어서 `/etc/passwd`, SSH 키, `.env` 파일을 다 읽을 수 있다.
- 위험 명령 차단 로직은 정규식 기반. 우회가 쉽다.
- Docker나 Modal 같은 격리 환경을 쓰면 오히려 approval 체크가 통째로 스킵된다.

노트북에 그냥 깔아두면, 안 쓰는 사이에 에이전트가(혹은 에이전트를 조종한 누군가가) 내 머신의 파일을 다 열어볼 수 있다.

### 위험 2: 자동 생성 스킬이 곧 prompt injection 표면이 된다

이게 더 미묘한 위험. 스킬 파일은 한 번 만들어지면 다음 세션에 자동 로드된다. 에이전트가 어떤 웹사이트 응답을 받아 그걸 스킬 절차에 포함시켰는데 그 응답에 악성 지시가 숨어 있었다면, 그 지시는 영구적으로 내 에이전트의 절차서에 박힌다.

공식 가드 로직이 있긴 한데 이것도 정규식이고, 에이전트가 만든 스킬은 위험이 발견돼도 사용자에게 묻는 등급으로만 처리된다. 매번 꼼꼼히 확인하지 않으면 그냥 통과한다.

### 위험 3: 자동 생성 품질이 들쭉날쭉하다

이건 공식 문서도 인정한다. 자동 생성된 스킬은 불필요한 단계가 끼거나 중요한 엣지 케이스를 놓치기 쉽다. 그래서 스킬이 반영되기 전에 사람이 한 번 보는 write-approval 게이트를 둘 수 있게 해뒀다.

스킬은 알아서 쌓인다. 쓸 만한 자산이 되는 건 사람 손이 주기적으로 들어간 다음.

### 위험 4: 메신저를 다 묶으면 자격증명도 다 묶인다

20개 넘는 채널을 하나의 게이트웨이로 묶는 게 셀링 포인트다. 거꾸로 말하면 그 게이트웨이 프로세스 하나가 뚫리면 텔레그램, 슬랙, 이메일이 동시에 노출된다.

## 깔지 말라는 건 아니다: 최소 운영 셋업

매력적인 건 맞다. 다만 켜놓고 잊을 수는 없고, 격리해두고 정기적으로 손보는 게 전제다. 내가 정리한 최소 셋업은 이렇다.

1. 호스트에 직접 깔지 말고 Docker 격리. 단, Docker 환경에서 approval 체크가 스킵되는 건 감안하고 쓴다.
2. 메신저는 처음에 하나만 연결. 익숙해진 다음 점진적으로 추가.
3. 스킬 폴더를 별도 git 리포로 묶어 자동 커밋. 새 스킬은 PR처럼 내가 한 번 본 다음 받아들인다.
4. 민감 디렉터리는 컨테이너 마운트에서 아예 제외.
5. 백엔드 LLM은 OpenRouter 단일 의존 말고 폴백 한 개 추가.

이 정도가 부담스러우면 내 워크플로에 Hermes가 정말 필요한지부터 다시 보면 된다.

## 운영하며 더 부딪히는 것들

위 네 가지 위험 말고도 굴리다 보면 만나는 지점들이다.

### 비용은 self-hosted라고 공짜가 아니다

내 서버라는 건 인프라 비용 얘기고, LLM 호출은 OpenRouter 같은 외부 API로 나간다. 자동 스킬 생성, 매 15회 회고 패스, cron 자동 작업까지 더하면 백그라운드에서도 토큰이 빠진다.

가벼운 개인용으로도 한 달 $30~100 보고가 흔하더라. 본격적으로 굴리면 더 나간다.

GPU 있으면 로컬 모델을 백엔드로 붙일 수 있다. NVIDIA가 DGX Spark와 묶어 띄운 이유가 그거다. 단 품질은 Claude나 GPT 대비 한 칸 아래로 보면 된다.

### 개인정보: 메시지가 그대로 LLM API로 나간다

텔레그램이나 슬랙에서 받은 메시지가 그대로 LLM API로 전송된다. 메시지 안에 타인의 개인정보가 섞여 있으면(예: 누가 보내준 누군가의 연락처) 내가 처리자 책임을 지는 그림이 된다. 한국이면 PIPA를 따져야 할 수도 있다.

업무용 슬랙은 연결 자체가 회사 정보보안 정책 위반일 가능성이 매우 높으니까, 여긴 확인 없이 못 넘어간다.

### 스킬은 백업해야 자산이 된다

`~/.hermes/skills/`에 쌓이는 스킬이 내 누적 자산인데, 컨테이너 한 번 날리면 그동안 학습이 다 손실이다. 별도 git 리포에 자동 커밋하는 cron 하나 두는 게 사실상 표준 패턴이다.

부가 효과로 내가 나를 PR 리뷰하는 흐름이 생긴다. 이상한 스킬이 끼어든 게 보이면 거기서 잡으면 된다.

### 0.x 버전: 유지보수에 정기 시간이 들어간다

현재 0.8대다. semver 0.x는 마이너 버전 업에서도 깨지는 변경이 들어올 수 있다. 빠르게 진화 중이라 2주만 안 들여다봐도 설정 포맷이 바뀌어 있더라는 보고가 잦다.

## 누구한테 맞고, 누구는 대체재가 낫나

용도별로 갈린다.

| 용도 | 더 나은 선택 | 이유 |
|---|---|---|
| 코딩 보조 | Claude Code, Cursor | 격리와 승인 흐름이 더 성숙 |
| 메신저 잡일 자동화 | n8n, Zapier | 룰 기반이라 예측 가능 |
| 장기 기억 챗봇 | ChatGPT Projects, Claude Projects | 간단하고 안전 |
| 자가학습 + 메신저 + 셸 권한이 한 곳에 필요 | Hermes Agent | 대체재 거의 없음 |

자가학습·메신저·셸 권한이 한 곳에 묶여 있다는 게 Hermes의 매력이다. 위험 표면도 정확히 거기서 나온다.

## 설치 전에 확인할 운영 비용

Hermes의 자동 학습은 분명 매력적이다. 다만 기본 설정의 보안 범위, 메신저 자격증명, 스킬 검토와 백업까지 함께 운영해야 한다. 이 부담을 감당할 환경이 아니라면 더 좁은 도구가 낫다.
