요즘 X와 해커뉴스에서 Hermes Agent라는 이름이 자주 보였다. 처음엔 그냥 또 하나의 LLM 래퍼겠지 싶어 넘겼는데, GitHub 별 17만 5천이 4개월 만에 붙었다는 숫자를 보고 마음이 바뀌었다. 이 정도 속도면 적어도 어디 한 군데는 사람들 가려운 데를 긁었다는 뜻이라서.

며칠 시간 내서 공식 문서, 보안 감사 리포트, 후기 글들을 훑어봤다. 결론은 단순하다. 매력적인 도구가 맞고, "깔고 쭉 쓰면 되는" 도구는 아니다. 정리해서 남긴다.

## Hermes Agent란?

에르메스 에이전트란 본인 서버에 깔아서 메신저랑 묶어 쓰는 장기 실행형 AI 에이전트다. NousResearch가 2026년 2월에 풀었고, 핵심 매력은 세 갈래로 갈린다.

- **self-hosted**: 본인 머신에 깔린다. 텔레메트리 없고, 클라우드 락인 없고, 데이터는 본인 디스크에 머문다.
- **메신저 통합**: 텔레그램, 디스코드, 슬랙, 왓츠앱, 시그널, 이메일까지 20개 넘는 채널을 하나의 게이트웨이 프로세스로 묶는다. "내 비서를 텔레그램에 두고 부른다"라는 그림이 실제로 가능해진다.
- **스킬을 스스로 만든다**: 셋째이자 진짜 차별점. 이게 다른 에이전트들과 가장 크게 다른 부분이다.

## 스킬을 스스로 만든다는 게 무슨 뜻이냐

평소 ChatGPT나 Claude를 쓰다 보면 답답한 순간이 있다. 어제 알려준 절차를 오늘도 다시 설명해야 한다. 메모리 기능이 있긴 하지만 "내가 누구다" 정도 저장이지 "이 작업은 이렇게 한다"가 누적되진 않는다.

Hermes는 다르다. 복잡한 작업을 끝내고 나면 (보통 도구 호출 5번 이상) 그 절차를 `SKILL.md`라는 파일로 자동 작성한다. 다음에 비슷한 요청이 오면 이 파일을 불러와서 그대로 실행한다. 실행하면서 새로 발견한 엣지 케이스가 있으면 스킬을 업데이트한다.

그와 별개로 주기적으로 백그라운드 회고 패스도 돈다. "이번 세션에서 뭐가 잘 됐지"를 보고 워크플로 파일을 저장한다.

이게 진짜로 동작한다. 처음 사람들이 열광한 게 이거였다. "오래 쓸수록 똑똑해진다"가 마케팅 카피가 아니라 진짜 기능한다.

## 그럼 깔고 쭉 쓰면 되는 거 아냐?

내가 처음 든 생각도 그거였다. 깔아두고 메신저 연결하고 일상 잡일 시키면서 알아서 똑똑해지길 기다리면 되는 거 아닌가.

아니다. 적어도 디폴트 그대로는 아니다.

### 위험 1: 디폴트 보안 자세가 ALLOW-ALL이다

이 부분은 마케팅 페이지엔 거의 안 나와서 직접 보안 감사 리포트를 봐야 알 수 있다. GitHub 이슈 #7826에 공식 감사 결과가 올라와 있고, Critical 4건, High 9건이 잡혔다.

핵심만 옮긴다.

- `env_type` 기본값이 `local`인데, 이 상태에서는 LLM이 **호스트 셸 명령을 무엇이든 실행 가능**하다.
- `read_file` 도구에 deny list가 없다. `/etc/passwd`, SSH 키, `.env` 파일 다 읽을 수 있다.
- 위험 명령 차단 로직이 정규식 기반이라 우회가 쉽다.
- Docker나 Modal 같은 격리 환경을 쓰면 오히려 approval 체크가 통째로 스킵된다.

본인 노트북에 그냥 깔아두면, 본인이 쓰지 않는 사이에 에이전트가 (혹은 에이전트를 조종한 누군가가) 내 머신의 파일을 다 볼 수 있다는 뜻이다.

### 위험 2: 자동 생성 스킬이 곧 prompt injection 표면이 된다

이게 더 미묘한 위험이다. 스킬 파일은 한 번 만들어지면 **다음 세션에 자동 로드된다.** 만약 에이전트가 어떤 웹사이트의 응답을 받아서 그걸 스킬 절차에 포함시켰는데, 그 응답에 악성 지시가 숨어 있었다면, 그 지시는 영구적으로 본인 에이전트의 절차서에 박힌다.

공식 가드 로직이 있긴 한데, 이것도 정규식이고, agent가 만든 스킬은 위험 발견 시 차단이 아니라 사용자에게 묻는 등급으로만 처리된다. 본인이 매번 꼼꼼히 확인하지 않으면 그냥 통과한다.

### 위험 3: 자동 생성 품질이 들쭉날쭉하다

이건 공식 문서도 인정하는 부분이다. 자동 생성된 스킬은 불필요한 단계가 끼거나 중요한 엣지 케이스를 놓치기 쉬워서, 스킬이 실제로 반영되기 전에 사람이 리뷰하는 write-approval 게이트를 둘 수 있게 해뒀다.

요약하면 자동으로 누적되지만 자동으로 좋아지진 않는다. 사람 손이 주기적으로 들어가야 진짜 자산이 된다.

### 위험 4: 메신저를 다 묶으면 자격증명도 다 묶인다

20개 넘는 채널을 하나의 게이트웨이로 묶는 게 셀링 포인트다. 거꾸로 말하면 그 게이트웨이 프로세스 하나가 뚫리면 텔레그램, 슬랙, 이메일이 동시에 노출된다.

## 그래서 깔지 말라는 건가

그건 또 아니다. 매력적인 도구는 매력적인 도구다. 다만 "디폴트로 켜놓고 잊는" 도구가 아니라 "공들여 격리하고 정기적으로 관리하는" 도구라는 점만 받아들이면 된다.

내가 정리한 최소 운영 셋업은 이렇다.

1. 호스트에 직접 깔지 말고 Docker 격리. 단, Docker 환경에서 approval 체크가 스킵된다는 점은 알고 있어야 한다.
2. 메신저는 처음에 하나만 연결. 익숙해진 다음 점진적으로 추가.
3. 스킬 폴더를 별도 git 리포로 묶어 자동 커밋. 새 스킬은 PR처럼 본인이 한 번 본 다음 받아들인다.
4. 민감 디렉터리는 컨테이너 마운트에서 아예 제외.
5. 백엔드 LLM은 OpenRouter 단일 의존 말고 폴백 한 개 추가.

이 정도 셋업이 부담스러우면, 본인 워크플로에 Hermes가 정말 필요한지부터 다시 보는 게 맞다.

## 추가로 신경 써야 할 것들

위 네 가지 위험 외에도 운영하면서 부딪힐 만한 포인트들이 있다. 정리해둔다.

### 비용은 self-hosted라고 공짜가 아니다

본인 서버라는 건 인프라 비용 얘기고, LLM 호출은 OpenRouter 같은 외부 API로 나간다. 자동 스킬 생성, 매 15회 회고 패스, cron 자동 작업까지 더하면 **백그라운드에서도 토큰이 빠진다.**

가벼운 개인용으로도 한 달 $30~100 보고가 흔하다. 본격적으로 굴리면 그 이상 각오해야 한다.

GPU 있으면 로컬 모델을 백엔드로 붙일 수 있긴 하다. NVIDIA가 DGX Spark와 묶어서 띄운 이유가 그거다. 단 품질은 Claude나 GPT 대비 한 칸 아래라고 보면 된다.

### 개인정보가 어디로 흐르는지 신경 써야 한다

텔레그램이나 슬랙에서 받은 메시지가 그대로 LLM API로 전송된다. 메시지 안에 타인의 개인정보가 섞여 있으면 (예: 누가 보내준 누군가의 연락처) 본인이 처리자 책임을 지는 그림이 된다. 한국에서 PIPA 따져야 할 수도 있다.

업무용 슬랙을 연결하는 건 회사 정보보안 정책 위반일 가능성이 매우 높다. 시작 전에 확인하자.

### 스킬은 백업해야 자산이 된다

`~/.hermes/skills/`에 쌓이는 스킬이 본인의 누적 자산인데, 컨테이너 한 번 날리면 그동안 학습이 다 손실이다. 별도 git 리포에 자동 커밋하는 cron 하나 두는 게 사실상 표준 패턴이다.

부가 효과로 본인이 자기 자신을 PR 리뷰하는 흐름이 생긴다. 이상한 스킬이 끼어든 게 보이면 거기서 잡을 수 있다.

### 0.x 버전 운영 부담을 받아들여야 한다

현재 0.8대다. semver 0.x는 마이너 버전 업에서도 깨지는 변경이 들어올 수 있다. 빠르게 진화 중이라 2주만 안 들여다봐도 설정 포맷이 바뀌어 있더라는 보고가 잦다. **한 번 깔고 잊는 도구가 아니라 유지보수에 정기 시간 투입이 필요한 도구**라는 뜻이다.

## 그래서 누구한테 추천하나

용도별로 정리하면 이렇게 갈린다.

| 용도 | 더 나은 선택 | 이유 |
|---|---|---|
| 코딩 보조 | Claude Code, Cursor | 격리와 승인 흐름이 더 성숙 |
| 메신저 잡일 자동화 | n8n, Zapier | 룰 기반이라 예측 가능 |
| 장기 기억 챗봇 | ChatGPT Projects, Claude Projects | 간단하고 안전 |
| 자가학습 + 메신저 + 셸 권한이 한 곳에 필요 | Hermes Agent | 대체재 거의 없음 |

마지막 줄이 핵심이다. Hermes의 매력은 남이 묶어주지 않은 조합을 한 곳에 묶었다는 것이고, 그 조합 자체가 위험 표면이다. 본인 워크플로가 그 조합을 정말로 필요로 하는지가 도입 결정의 출발점이다.

## 마무리

내가 내린 결론은 이거다. Hermes는 흥미로운 도구다. 다만 마케팅 카피의 "self-improving"이라는 표현이 주는 인상과 실제 운영 부담 사이 간극이 꽤 크다. 깔기 전에 "내가 이 정도 보안 격리와 정기 유지보수를 감당할 수 있나"부터 자기 자신한테 물어보는 게 순서다.

본인은 일단 Docker 격리 환경에서 메신저 한 개만 붙여서 한 달 정도 굴려볼 생각이다. 한 달 뒤 후속 글로 실제 비용, 누적된 스킬 품질, 깨진 부분을 정리해서 또 올리겠다.
